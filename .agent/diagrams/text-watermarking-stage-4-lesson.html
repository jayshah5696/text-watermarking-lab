Text watermarking lab / Stage 4

Check the loop against a maintained library

Stage 3 showed every operation by hand. Now we give the same kind of job to Transformers 5.14.1 and inspect what it actually does.

When Transformers replaces our hand-written loop, which steps stay the same, and which exact details change?

Short answer. The same four ideas remain. A key marks green token IDs. Model preference numbers change. A saved random draw chooses one token. A checker rebuilds green hits from copied text. The operation order and complete recipe differ, so the two implementations are related but not interchangeable.

The complete story without animation

Transformers divides the preference numbers by 0.8, keeps the 40 highest choices, keeps the smallest leading group reaching 95 percent, then adds 2 to surviving green choices. This leaves 19 choices and gives was an 8.642730% chance.

The earlier order adds 2 first, divides by 0.8, applies the 95 percent filter, then keeps at most 40. It leaves 11 choices and gives the same token an 8.825517% chance. Only the Transformers order generated the saved continuation.

Formula, cutoff, and approximate p-value

The evidence score is z = (G - 0.25T) / sqrt(T * 0.25 * 0.75). For 17 green hits in 39 decisions, z is 2.6810509484219405. Transformers uses the strict rule z > 3.0, so equality would still be false.

The recorded approximate p-value is 0.0051477689636219015. It is an upper-tail calculation under the configured random model. It is not a measured false-positive rate and does not identify who wrote the text.

Padding and prompt exclusion

The three prompt encodings contain 13, 11, and 9 tokens. Left padding makes each row width 13 with 0, 2, and 4 pad tokens. The continuation slice starts at position 13. The primary detector receives 0 prompt tokens and 0 padding tokens. GPT-2 token ID 50256 serves as both end and pad token for this batch.
