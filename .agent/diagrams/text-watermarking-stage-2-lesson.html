02

What the key is and why the code needs one

A key is a value that the system operator gives to the watermark code. The model does not learn it. The prompt and generated text do not need to contain it.

Teaching key

The repository author chose this value

stage-02-public-demo-key-v1

We show this key so anyone can repeat the lesson. It is a readable label for teaching. It is not a secure production secret.

The generator uses the key before sampling

SHA-256 turns the key, recent token numbers, and candidate number into a fixed-length result. A small change to the input usually gives a different result. The selector runs this calculation for all 20 candidates, sorts the results, and marks the first five. The same key, context, and vocabulary produce the same five marked words.

The checker uses the key after generation

The checker reads the previous four tokens and uses the matching key to rebuild the selected set.

The operator stores the key outside the model

The operator can change it without retraining the model. Every model and tokenizer setup still needs its own quality and detection tests.

Why the code defines a key

The generator and checker need a repeatable selection rule. Both use the same key, so they do not have to store a new list of marked words for every position.

The selector marks words. The sampler then uses a random number to choose the next word.

In this lesson, we print the key so readers can repeat the calculation. A production service would normally keep its key secret. The key does not encrypt the sentence, and it is not a password or an API key.

Who chooses it

The organization that runs the generator normally controls the key.

What people normally use

A production design would use random secret bytes from a cryptographic random generator. The exact size and format depend on the chosen method.

Where it normally lives

The operator would keep the secret in protected key storage and give it a separate public name.

The operator gives each secret a public name

The checker uses that name to find the right secret. The selector uses the secret value in its calculation.

The two fixed key results

With the context Early one morning Jack, the lesson key marks Early, went, walked, snow, and trail green.

The comparison key marks the, hill, path, snow, and home green. Both keys mark five of 20 words.

How the program builds the pattern across positions

A word does not have one permanent green or red label. The selector ranks the vocabulary again for each context. The document pattern is the sequence of green hits across many checked positions.

If an operator changes the key during generation, the sampled word may change. That word enters the next context, so later groups may also change. If a checker changes the key for finished text, the words stay fixed. Only the rebuilt groups, hit count, and z score change.

The key affects the count before the formula runs

The key does not appear in the z score formula. It changes which observed tokens count as green hits. The formula then uses only G, T, and the 25 percent baseline.

This result describes how the text matches this toy selector, key, token mapping, and settings. It cannot identify the writer or prove that AI produced the text.

Show the Stage 1 calculation for this sentence

The checker found G = 2 hits in T = 4 positions. Random selection predicts 4 times 0.25 = 1 hit. The usual spread is 0.8660.

z = (2 - 1) / 0.8660 = 1.1547

The score says how far the hit count sits above the 25 percent teaching baseline. A cutoff would be a separate rule for making a decision.

05

How an operator stores a production key

To rebuild the marked sets and count hits, the checker must match the key, token numbering, selection rule, four-token window, fraction of words that the selector marks, and counting rule. It does not need the score increase or the random numbers used during generation.

A production operator would generate an unpredictable secret and store it outside prompts and browser code. The operator would limit access and assign a public name to the secret. The operator would also decide when old keys should be replaced. The operator should record the score increase because it affects how strong the pattern is and which cutoff later tests may support.

We use a public teaching key for repeatable examples. This value provides no secrecy. Someone who knows it may find it easier to copy or remove the pattern.
